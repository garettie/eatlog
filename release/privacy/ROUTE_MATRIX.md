# Eatlog route and data matrix

Source audit: 2026-09-24, `84461b0..HEAD` plus this preview worktree. This records code behavior for copy and store forms; it is not a record of a device run or a deployed service.

| Feature | Access and choice | Outgoing data, recipient, credential | Stored state, deletion, and limits | User-facing locations |
| --- | --- | --- | --- | --- |
| Manual food, saved meals, weights, targets, Diary, Analytics, adaptive suggestions | Free; no key or AI consent | None from these actions | App-private SQLite and meal photos; user edits/deletes, backup/restore, Delete all data. Adaptive changes require acceptance | Add, Today, Diary, Analytics, Profile |
| Camera, gallery, and local past-meal reuse | Free; camera/picker permission at action | No estimate upload on capture, selection, or reuse | A chosen image is copied to app-private storage for a saved meal; Delete all data removes it | Add, Identify meal, review |
| My key photo/description estimate and meal/component re-estimate | Saved key and My key route; key acceptance is separate from hosted consent | Selected resized photo plus optional title, or typed description; clarification adds source text and current component names/grams. HTTPS direct to Google Gemini with `x-goog-api-key`. No Eatlog Worker, install ID, RevenueCat grant, or hosted quota call for the estimate | Google key in SecureStore, masked first/last four on AI estimates screen; route/consent in separate app file. Key and record excluded from SQLite, backup, CSV. Replace keeps route, Remove key and Delete all data erase local key; revocation at Google is separate. Google's project/model/region quota, charges, and data terms apply | Profile → AI estimates, Add, meal review, Privacy |
| My key validation | User presses Save or Replace after entering key | Key in `x-goog-api-key` to Google's model-list endpoint; no meal photo or description | Key is saved only after validation succeeds. Google can receive key and request metadata before the first estimate | Key setup and replacement |
| Eatlog AI photo/description estimate and meal/component re-estimate | Active Omelette, legacy paid, or complimentary entitlement; separate accepted hosted consent | Selected estimate body to Worker `/v1/estimate` with app installation ID, request ID, optional signed grant; Worker forwards content to Gemini. On territorial refusal it retries the same model via `wnam`-pinned GeminiRelay Durable Object | Worker stores salted quota subject, reservation/idempotency and usage records, not meal content. 30 combined operations per rolling 24h, 250 per rolling 30d; five rejected-food refunds per rolling day. Paid entitlement and consent checked independently. Withdrawal blocks future hosted estimates. Local Delete all data does not remove Worker or store records | Profile → AI estimates/Plan/Privacy, Add, meal review |
| USDA search/detail | Free; online search or result tap; no AI consent | Rewritten query/mode or numeric food ID, installation ID to Worker; Worker uses owner USDA key | Short app-memory cache; Worker upstream cache and IP/install throttling. Logged foods enter SQLite. Local reset clears app data, not provider logs | Search foods |
| Open Food Facts | Free; explicit full search | Rewritten query direct to `search.openfoodfacts.org`, app User-Agent with support contact; no Eatlog key | Short app-memory cache; logged foods enter SQLite. Provider handles request under its terms | Search foods, attribution |
| Store access, purchase, restore, usage | Plan screen or SDK refresh; paid purchase optional | Random installation ID as RevenueCat App User ID; store/RevenueCat process product, receipt, entitlement. Worker `/v1/access/refresh` and `/v1/usage` receive install ID/grant; no food content | RevenueCat SDK cache, in-memory signed grant, Worker salted quota and entitlement cache. No receipts/grants/quota in SQLite, backup, CSV. Store refund/revocation and legacy subscription management remain store-controlled | Profile → Plan, purchase/restore/manage |
| Installation identity | Generated per install; used for Worker and RevenueCat requests | Random app-scoped token, not a name or advertising ID | App-private file outside SQLite/backup/CSV; app removal regenerates. Delete all data does not currently erase it or remote quota history | Plan Support ID and privacy disclosure |
| Health Connect Weight | Android only, user connects and grants Weight permissions | Weight records to/from Android Health Connect; none to Eatlog Worker | Weight history and sync metadata in SQLite. Disconnect/revoke in Android; reset attempts cleanup of Eatlog-written records; exported copies remain with recipient | Profile → Health Connect/Privacy |
| Backup, restore, CSV, meal sharing | Free, user-initiated | `.eatlog-backup` or legacy archive selected through Files; CSV ZIP or rendered meal PNG to destination the user selects in system share sheet. No Eatlog server | Backup contains SQLite and referenced photos, excludes key, consent, install ID, grants, quota, and Health Connect sync authority. CSV is readable but not restorable. Share cache is temporary. Delete all data removes app copies, not external copies | Profile → Backup/Export/Delete all data, Diary → Share |
| Support and policy links | User opens a public URL or chooses email | Browser/email app receives normal request or drafted support message; Support ID only if user copies/sends it | External app/provider controls copies. Eatlog has no support-chat backend | Profile → Support/About/Privacy |
| App updates | Installed build with Expo Updates | Expo update request metadata to the configured EAS channel/service; no diary payload in app code | Expo/platform may cache update bundles and operational request metadata. Native billing changes require a new preview binary and compatible runtime | Startup/update service; release configuration |

The My key estimate payload never reaches Eatlog's Worker. That does **not** mean the app never contacts Eatlog: USDA, hosted AI, and access/usage checks do, and the app also checks RevenueCat and Expo updates. Google controls My key availability and billing. Under [Gemini API terms](https://ai.google.dev/gemini-api/terms), unpaid API usage can be used for product improvement and human review; a billed Google Cloud project has different treatment, and the EEA, Switzerland, and UK have an exception. Buying Omelette does not change the user's Google project category.

Hosted consent version 1 remains valid for users who accepted its existing Worker-to-Gemini disclosure. Saving a My key no longer accepts hosted consent on the user's behalf. The Privacy control names hosted scope, and My key removal remains on AI estimates. A material future change to recipients or payloads needs a separate consent-version review.
